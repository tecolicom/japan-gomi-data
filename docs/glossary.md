# 用語集

同じものを別の名で呼んでいて話が通じなくなることがあったので、**呼び方を 1 つに決める**。
既存文書には揺れが残っている (2026-08-15 時点で「コース」81 / 「地区」78、
「extractor」87 / 「生成器」27、「照合」125 / 「検証」78)。**一括置換はしない** —
以後の書き方をここへ寄せる。

## 1. データの単位とファイル

| 用語 | 意味 |
|---|---|
| **handle** | 自治体の識別子 (`mitaka`)。自分で綴らずレジストリで引く。ディレクトリ名になる |
| **course** | **同一日程のまとまり**。`metadata.course` が正式な値で、下流はこれで識別・表示・URL 生成する。**値を変えない** |

> **course の識別は、データを読むすべての経路で `metadata.course` に揃っている必要がある。**
> ファイル名 (`course-<metadata.course>.yaml`) は `writeCourses` が決める副産物にすぎない。
> 2026-08 に飯能で `course-A1.yaml` → `course-A-1.yaml` と改名したとき、city.tecoli の
> ページは `metadata.course` を見ていたのに `.ics` 生成ツールだけがファイル名を
> 決め打ちしていて、取り込み直後のビルドが落ちた。**片方だけが約束を守っていても壊れる。**
| コース / 地区 / 日程 | 自治体側の呼称。三鷹は「地区」、青梅は「日程」、飯能は「コース」。**データ上はすべて course** |
| **area** | 1 町名 (丁目単位)。`{name, yomi?, machiaza_id?, note?}` |
| **収録期間** | `YYYY-MM--YYYY-MM`。**一次ソースが実際に裏付ける範囲**であって会計年度ではない |

`municipalities/<県>/<handle>/` に置くファイルは役割が違う。**どれが真実かを取り違えない。**

| ファイル | 何の正典か |
|---|---|
| `survey.yaml` | **調査記録**。一次ソースの所在・形式・罠。収録前に書き、収録後も残す |
| `meta.yaml` | **運用ルールと検証記録**。祝日・年末年始の扱い、確率的信頼度 |
| `taxonomy.yaml` | **その自治体の語彙**。`schema/categories.yaml` の部分集合 + `groups` (市の呼称) |
| `facts.yaml` | **読み物断片** (任意)。出典必須 |
| `<収録期間>/course-*.yaml` | **日程本体**。多くは生成物 (下記「正典」を見よ) |

## 2. 処理と検査

| 用語 | 意味 |
|---|---|
| **生成器** | `tools/<形式>-extractor/<handle>/` 一式。コード上の名前は **extractor**。日本語では生成器で統一する |
| **抽出 (extract)** | 一次ソース → 中間データ。PDF・HTML・CSV を読む段 |
| **生成 (build)** | 中間データ → `course-*.yaml`。`build.mjs` が担う |
| **一次ソース** | 日程の出どころ。自治体が公開しているもの |
| **独立照合ソース** | 一次ソースとは別経路で同じ日程を表しているもの (別レイアウトの PDF、冊子本文の頻度規則など)。**無いなら「無い」と明言する** |

検査は 3 つあり、**見ているものが違う**。混同すると「検査したつもり」になる。

| 検査 | 何と何を比べるか | 実行 |
|---|---|---|
| **自己検証** | `build` が作った規則を再展開した結果 ↔ 抽出した実日付 | `build.mjs` の中。合わなければ書き出さない |
| **照合 (verify)** | 生成物 ↔ **独立照合ソース** | `node verify.mjs` |
| **regen** | 生成物 ↔ **git 管理下の内容** | `make regen HANDLE=..`。差分ゼロなら再現できている |

- **regen が skip する自治体は「検査されていない」**。差分ゼロとは違う。飯能はこれで誤りを 4 か月配信した
- **「不一致 0」を報告する前に、1 日ぶん書き換えて差分が出ることを確かめる** (存在する日付を狙う)

| 用語 | 意味 |
|---|---|
| **正典 (canon)** | そのファイルの真実がどちらにあるか。生成器が書くファイルは**生成物**で手編集しない。生成しないファイルは**手書きが正典** |
| **収録** | 新しい自治体のデータを作ること |
| **再構築** | 収録済みだが生成器が無い自治体に、生成器を起こすこと (`docs/playbook.md` §6) |

## 3. 規則の語彙

`schema/schedule.schema.json` の `pattern` は 3 つだけ。

| 用語 | 意味 |
|---|---|
| **weekly** | 毎週その曜日 |
| **monthly_nth** | **その月 n 回目の該当曜日**。`occurrences` は 1〜5 の**肯定リスト**で、除外を書く構文は無い |
| **monthly_specific** | 実日付の列挙。規則化できないものの退避先 |

- **「第n週」ではない。**「1 日が土曜の月は第 1 週に月曜が無いが、1 回目の月曜は第 2 週にある」。
  実装は `tools/_lib/schedule.mjs` の `nthOfMonth`、日本語表記のパースは `tools/_lib/jp.mjs`
- **「5 回目だけ無し」は `[1,2,3,4]` と書く** (除外構文が無いため)。現に使っている自治体は無い

`overrides` は日付単位の例外。`tools/_lib/schedule.mjs` の `categoriesOn` が次のように扱う。

| 書き方 | 効果 |
|---|---|
| `{date, cancelled: true}` | **その日は全休止**。category は見ない |
| `{date, category}` | **その日の monthly 系を丸ごと捨て**、weekly + この category を残す。複数品目があるなら**全部並べる** |

| 用語 | 意味 |
|---|---|
| **繰り下げ** | 休業日のぶんサイクルが後ろへずれること。飯能 A-2・三鷹の 2 地区が該当し、**規則では表せないので override に落とす** |
| **休止** | その日に収集が無いこと。`cancelled` で表す |

### 未採用の語彙 (`docs/drafts/` の草案にしかない)

**現行スキーマには無い。** 実装や議論で使うときは草案の話だと明示する。

| 用語 | 意味 |
|---|---|
| `eligible_nth` | **非休業ベース**の第 n 該当曜日 |
| `cycle` | 非休業曜日に対する周期列。休業日はサイクルを消費しない |
| `weekno_nth` | 第 n カレンダー週の曜日 |

## 4. 文書の呼び方

「ガイド」「資料」「設計」ではどれを指すか決まらない。**ファイル名か下の呼称で呼ぶ。**

| 呼称 | ファイル | 中身 | 状態 |
|---|---|---|---|
| **不変条件** | `AGENTS.md` | 守らないと壊れるもの。触ってよい場所 | — |
| **プレイブック** | `docs/playbook.md` | 収録の**知識**。ソース判定・実装・照合・再構築 | — |
| **スキル** | `.claude/skills/add-municipality/SKILL.md` | 収録の**進行管理**。停止点と承認項目 | — |
| **調査記録** | `docs/opendata-sources.md` | 自治体別の調査メモ +「検証の考え方」 | — |
| **オンボーディング設計** | `docs/2026-08-10-contributor-onboarding-design.md` | 貢献者が回せるようにする設計 | **採用済み**。**第 1 段** (入口と足場) は実装済み、**第 2 段** (schema と生成物 = `provenance`/`summary`/`coverage.md`) は**未着手** |
| **メタルール草案** | `docs/drafts/2026-07-20-meta-rule-format-draft.md` | 年度カレンダーではなく**生成規則を正典にする**構想。毎年のカレンダーを休業期間だけから生成する | **未採用** |

> 「メタデータ」は曖昧なので使わない。`meta.yaml` / `facts.yaml` / `taxonomy.yaml` と呼ぶか、
> オンボーディング設計の `source.provenance` / `meta.summary` を指すのか明示する。
