# 門真市 ごみ収集日抽出 (html-extractor/kadoma)

門真市「地区別ごみカレンダー」ページ (HTML) の表から規則を作り、地区別カレンダー PDF と全日照合して
`municipalities/osaka/kadoma/` の course YAML を生成するパイプライン。
meta.yaml / taxonomy.yaml は生成しない (手書きが正典)。

## 一次ソース

- 地区別ごみカレンダー: `https://www.city.kadoma.osaka.jp/kurashi/gomi/9/35805.html` (`sources.mjs`)
  - A〜F の 6 地区ごとに、町名の段落と「品目 / 収集日」の表 (7 行。粗大ごみを含む)
- 地区別 PDF: `material/files/group/20/{A..F}.pdf`。A3 縦 2 ページの日付入りカレンダー
- **収録期間 2026-04--2027-03** は PDF の見出し「令和8年4月1日～令和9年3月31日」による。HTML には期間が無い
- ライセンス明示なし (サイトポリシーは出典明示で転載可・改変不可)。収集日という事実データを抽出して収録する

## パイプライン

```
node fetch.mjs                          # 案内ページ・PDF 6 枚・ABR 町字マスター (大阪府版) を cache/ へ (--force で取り直し)
EXTRACTED_AT=YYYY-MM-DD node build.mjs  # cache → 2026-04--2027-03/course-*.yaml (照合つき)
node verify.mjs                         # 生成 YAML を読み直して PDF・HTML の文と全日比較
node --test parse.test.mjs
```

`extract.py` は PDF の罫線と塗りつぶし図形の座標を JSON で出すだけで、解釈は `parse.mjs` が行う。

## HTML (parseIndex)

`<h3>A地区</h3>` の後ろに町名の `<p>` と `<caption>A地区の収集日</caption>` の表が続く。
表の品目は 7 つで、知らない品目・足りない品目は throw する。

- 「毎週火曜日・金曜日」→ weekly。`jp.mjs` の `parseWeeklyJa` は読めない片を黙って落とすので、曜日の数を数え直す
- 「毎月第1・3水曜日」→ monthly_nth
- 町名: 「岸和田1丁目～4丁目」は 1 丁目ずつに展開、「北巣本町(1番～34番)」は「北巣本町（1番～34番）」

## PDF (parseCalendar)

文字はすべてアウトライン化されていて (chars 0) 日番号も品目名も曲線。読み方:

1. **月の枠**: 縦線 (高さ 220pt の細い rect) と横線 (幅 348pt) から、1 ページに 3 段 × 左右 = 6 か月の枠を取る。
   各枠は縦線 8 本・横線 7 本 (曜日見出し + 5 週)。列幅は地区によって違う (F は火・金の列が狭い) ので固定しない
2. **マスの日付**: 暦から決める (日曜始まり 5 週)。6 週目の日は 5 週目の同じ曜日のマスに 2 つ並ぶ
   (「23/30」「24/31」)。そのマスは両日の HTML の日程が同じであることを確かめてから照合する
3. **日付の確かめ**: マスの上端 14pt の帯に日番号の色 (黒・赤・土曜の青 2 種) の図形があるのは、
   日付のあるマスだけであることを全マスで assert する。月の並びや曜日の位置がずれると止まる
4. **品目**: 帯より下の図形を色でまとめ、凡例 (アイコンの下の品目名の行) の色に最も近いものに当てる

罠:

- **アイコン画像のハッシュでは分類できない。** 同じ品目でも月・地区によって画像が作り直されている (1 枚に 20 種以上)
- **凡例とマスで品目名の色が少し違う地区がある** (A 地区のプラ容器: 凡例 0.549,0.075,0.484 / マス 0.453,0.201,0.561)。
  完全一致ではなく最も近い色で選び、2 番目に近い色と 2 倍以上離れていることを確かめる
- **同じ字形が 0.2pt ずらして 2 重に描かれていることがある** (C 地区の 8 月・12 月の「びん・缶類」)。畳んでから数える
- 品目名の図形の数はマスによって 1 つ前後する (E 地区 6/3 の「小型ごみ」は 14、ほかは 13)。数の一致は求めず、8 個以上あることだけを見る

## 規則の作り方 (build.mjs)

規則は HTML の表の文から作る。PDF と全 365 日を比べ、食い違ってよいのは
**年末年始 (12/29〜1/3) に PDF が空欄の日**だけで、その日を cancelled にする。それ以外の食い違いは throw。
最後に rules + overrides を `expandRange` で再展開し、HTML の日程から休止日を除いたものと全日一致することを確かめる。

ABR に無い町字・どの地区にも無い町字が、記録済みの 6 つ (大字門真など) から変わったら止まる。

## 照合 (verify.mjs)

1. 生成 YAML を再展開して、PDF を読み直した日程と全日比較 — 6 地区 × 365 日 = 2,190 日枠
2. HTML の表の文から数え直した日程と全日比較 (年末年始の休止日は文に無いので数えて報告する)
