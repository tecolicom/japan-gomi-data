## この村の特徴 — 抽出するのは日付ではなく規則

**日付入りカレンダーが存在しない。** 表の「指定日」欄に「月・木曜日」「第1・2・3・5 金曜日」
のように**曜日規則が文章で書かれている**のが唯一の資料である。したがって
`classifyRules()` (実日付 → 規則) は使わない。表から規則を直接読む。

粗大ごみは自己搬入 (小川地区衛生組合) で集積所の対象外なので course に入れない。
ごみ処理は秩父広域市町村圏組合ではなく小川地区の枠組である。

## 罠

### 1. 「出せません」を肯定と読まない

資源回収は第2水と第4水で**出せる品目が違う**。

| 第2水 (役場前駐車場) | 第4水 (各ステーション) |
|---|---|
| 新聞、雑誌、段ボール<br>**（衣類やアルミ缶は出せません）** | 新聞、雑誌、雑がみ、牛乳パック、段ボール、**衣類**、**アルミ缶** |

第2水の欄には「衣類」も「アルミ缶」も**文字としては現れる**が、意味は逆である。
**収録時 (2026-08-03) に人がここを読み落とし、17 日間ぶん誤った収集日を配信した**
(第2水曜 12 日 × 2 品目)。`itemCategories()` が否定の括弧書きを先に切り離し、
同じ品目が肯定と否定の両方に現れたら throw する。

牛乳パックは第2水の一覧に無いが、正典語彙では `paper` に含まれ分離できないため
`paper` は第2・4水のままとする (語彙を勝手に増やさない)。

### 2. セル内の改行は規則の途中で切れる

`<br>` による折り返しなので、「第1・2・3・5」と「金曜日」が別行になる。
注記の `※` で切ってから改行を潰す。

### 3. 種別が 2 つに分かれていても正典では 1 つになる

村は「資源プラスチック (第1・2・3・5金)」と「廃プラスチック (第4金)」を別の種別として
書くが、どちらも正典語彙では `plastic` である。`mergeRules()` が同一品目・同一曜日の
規則をまとめ、**第 n が 1〜5 すべて揃ったときだけ** `weekly` に畳む。

同様に「ガラス類・ペットボトル」は 1 行に 2 品目 (`non_burnable` + `pet_bottle`)。
村に不燃ごみ区分は無く、ガラス類がこれに相当する。

### 4. 季節限定の追加収集は規則では書けない

「※ペットボトルは、5・6・7・8・9・10月のみ第1水曜日でも出せる」を表す語彙が
スキーマに無いので、該当日 6 件を `overrides` に落とす。

## 使い方

```sh
node fetch.mjs                              # HTML を cache/ へ
EXTRACTED_AT=$(date +%F) node build.mjs     # course-1.yaml を生成
```

## 検証

日付入りの資料が無いため、**規則を実日付に展開して突き合わせる相手が存在しない。**
代わりに parse が一次ソースの改訂を検出することを、6 通りの改竄で確認している。

| 改竄 | 期待 | 結果 |
|---|---|---|
| 「出せません」→「も出せます」 | 第2水にも衣類・アルミ缶が立つ | `cloth`/`beverage_can` が `[2,4]` に |
| 表の指定日 第4水 → 第5水 | 規則が追随する | `[4]` → `[5]` |
| 資源プラ 第1・2・3・5金 → 第1・3金 | weekly に畳めなくなる | `plastic` が `[1,3,4]` に |
| 季節限定 5〜10月 → 6〜8月 | 月が追随する | `months` が `[6,7,8]` に |
| 種別名を変える | 表の改訂として止まる | `CATEGORY_MAP に無い種別` で throw |
| 注記の語尾を変える | 未対応表記として止まる | `未対応の注記` で throw |

**最初の改竄テストは空振りした。** 「第4水曜日」を単純置換したが、HTML 内の最初の
出現は本文の注記 (「衣類は貴重な資源（第4水曜日に各ステーションへ）」) で、表の中では
なかった。結果が変わらないのを「検査が効かない」と誤読しかけている。
**改竄はそれが本当に狙った場所に当たったかを確かめる。**
