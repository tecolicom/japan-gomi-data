# 三鷹市 収集日程抽出 (html-extractor/mitaka)

三鷹市「収集日程」(令和8年度 = 2026年4月〜2027年3月) の**地区別 HTML** から
`municipalities/tokyo/mitaka/` の course YAML を生成するパイプライン。

## 一次ソース

- 索引: https://www.city.mitaka.lg.jp/c_categories/index01004001001.html
- 地区別: `/c_service/095/0956{64,66,67,71,74,77,80,82,85,87}.html` (**10 地区**)

各ページに曜日規則の表が 1 つある。

```
月曜日  燃やせるごみ
火曜日  古紙・古着
水曜日  プラスチック類 有害ごみ 第1・3 燃やせないごみ
木曜日  燃やせるごみ
金曜日  第1・3 ペットボトル 第2・4 空きびん・缶
```

ライセンス明示なしの通常ページ。市のオープンデータに収集日程データセットは無いため、
**収集日という事実データを抽出**して収録する (練馬・杉並・調布・青梅と同じ整理)。

> **survey の訂正**: `survey.yaml` は「地区は 11」としていたが、令和8年度の地区別ページは **10 本**。
> ABR の三鷹市 62 町字をちょうど過不足なく分割するので、10 が正しい。

## パイプライン

```
node fetch.mjs [--force]                   # 索引から地区別 HTML を辿って cache/ へ
node fetch-yomi.mjs                        # ABR 町字マスター(pref13)から三鷹市62町字を cache/abr-town.json へ
python3 extract-yearend.py cache/pdf/*.pdf # 地区別カレンダーPDF → 年末年始の休止日・注記
  > cache/yearend.json
EXTRACTED_AT=YYYY-MM-DD node build.mjs     # 曜日規則 + 年末年始 → course-*.yaml
node verify.mjs                            # PDF (機械抽出 + 目視転記) と照合
```

`cache/pdf/` の PDF は各地区ページの添付 (2 か月ごと 6 本のうち「2026年12月・2027年1月」版) を
手で置く。`extract-yearend.py` は `pdfplumber` を使う。

## パースの要点 (parse.mjs)

- **caption が揺れている。** 9 地区は「ごみ・資源物の収集日程」だが 095677 だけ「ごみ・資源物の収集日」。
  前方一致で拾う。
- **「第n・m」は直後の 1 品目だけに掛かる。**「第1・3 空きびん・缶 第2・4 ペットボトル」が
  成り立つため。「プラスチック類 有害ごみ 第1・3 燃やせないごみ」ならプラと有害は毎週。
- **地区名の「・」は町の区切りにも丁目の区切りにも使われる** (「野崎2・3丁目」)。
  町名で始まらない断片は直前の町の続きとして読む。「全域」はその町の全丁目。
- build は **ABR の 62 町字を 10 地区へ重複・欠落なく分割できること**を検査する。
  地区名のパースが狂えばここで落ちる。

## 種別マッピング

| HTML 表記 | category |
|---|---|
| 燃やせるごみ | `burnable` |
| 燃やせないごみ | `non_burnable` |
| プラスチック類 | `plastic` |
| 有害ごみ | `hazardous` |
| ペットボトル | `pet_bottle` |
| **空きびん・缶** | `glass_bottle` + `beverage_can` |
| **古紙・古着** | `paper` + `cloth` |

複合語 2 つは構成カテゴリへ分解する (日程情報の欠落はゼロ。同日性は days 共有で明示される)。
市の呼称は `taxonomy.yaml` の `groups` に残した。

## 年末年始 — HTML には無い

HTML には「年末及び1月は収集日程、時間が異なることがあります。下記添付ファイルでご確認ください」
とあるだけなので、**地区別カレンダー PDF から読む**。設定は `sources.mjs` にあり、
`verify.mjs` が PDF と突き合わせて裏を取る。

| | |
|---|---|
| 12/30・12/31・1/1 | 全 10 地区が休止 |
| **12/29 (火)** | **地区で分かれる。**「※12月29日（火）の可燃は臨時に収集します。」の注記がある 5 地区 (いずれも火曜が可燃) は収集し、残る 5 地区は休止 |
| **1 月の繰り下げ** | 1/1 (金) が休みになるため、**金曜に「第n」枠を持つ 2 地区だけ** 1 週ずれて第 5 金曜にも収集がある。PDF に「※空きびん・缶は2回目と4回目、ペットボトルは3回目と5回目に収集します。」と明記。他の曜日は 1/1 の影響を受けないので繰り下がらない |

## 照合 (verify.mjs)

品目マークは 1 枚の画像に埋め込まれていて**テキストにならない** (`chars` はカレンダーの日番号と
注記だけ)。そこで 3 段構えにしている。

1. **休止日** — 「ありません」の直上にある日番号を同じセルの日付とみなして機械抽出。全 10 地区
2. **注記** — 「臨時に収集」「n回目と…」の断片の共存で判定。全 10 地区
3. **カレンダー本体** — 目視転記。繰り下げのある 2 地区の 12 月・1 月を全日 (88 日枠) 書き出し、
   `PDF_SAMPLES` に固定保持している

```
地区 10 / 目視転記 88 日枠 / 不一致 0
```

`PDF_SAMPLES` を 1 日ぶん書き換えると差分として出ることを確認済み。

> 注記のテキストは**隣のセルの文字と座標順に混ざって出てくる**
> (「※12月29日（火）の注意注意可燃は臨時に収集年末のため、…します。」)。
> 連続した文字列としては読めないので、断片の共存で判定している。

### 残っているリスク

4〜11 月・2〜3 月の月次カレンダー PDF は目視していない。HTML の曜日規則と PDF が食い違う可能性は
残る (確率的信頼度は `meta.yaml` の notes を見よ)。次年度の更新時にサンプルを足すとよい。
