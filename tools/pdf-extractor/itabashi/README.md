# 板橋区 (itabashi) — 地域別 資源回収・ごみ収集曜日カレンダー

```
node fetch.mjs                           # cache/ に 24 PDF + 索引 HTML + ABR を揃える
EXTRACTED_AT=2026-09-01 node build.mjs   # course-*.yaml を生成
node verify.mjs                          # 地区割の双方向照合 + 日付レベル全数照合
node verify.mjs --tamper                 # 検査が実際に落ちることを確かめる
```

`meta.yaml` / `taxonomy.yaml` は**生成しない**。手書きが正典。

## 区は同じ日程を 2 通りに公表している (どちらも機械可読)

| | 中身 | 使い道 |
|---|---|---|
| 地域別カレンダー PDF (24 本) | 令和8年4月〜令和9年3月の通年カレンダー。**テキスト層に曜日規則が明記**され、本体は 3 色の塗りセル (ピンク=可燃 / 緑=資源 / シアン=不燃)。ヘッダに「地域 → 町丁目」 | **一次ソース** |
| 索引ページの HTML 表 (70 行) | 町丁目 × 資源/可燃/不燃 の曜日 + 地域番号。「町丁目 → 地域」 | 照合 + 地区割の正典 |

1 本の PDF が**規則と実日付の両方**を持ち、HTML が**別に組まれた第 3 の表現**を持つ。
読み取り経路も違う (PDF は塗り色、HTML は文字) ので、照合の独立性が高い。

URL の置き場が東西で違う — 西は `r8/w01.pdf`、東は `r8/higashi/nishi/e01.pdf` (区側の名残)。

## 踏んだ罠

| 罠 | 何が起きたか | 対処 |
|---|---|---|
| **月ブロックの左右** | 1 ページに 2 か月 × 6 段。「月見出しの x から一定幅」で判定したら右の月のセルが左の月に吸われ、**偽の欠け 27 件・偽の余り 8 件**が出た | 見出しの x の最小と最大の**中点**で左右を分け、その列の直上の見出しを採る |
| **曜日列の対応** | ヘッダ語「水Wed」はセルの中に**中央寄せ**で置かれ、セルの左端はヘッダ語の左端より 7.3pt 外側。左端どうしで比べると対応が取れない | セルとヘッダの**中心**どうしで対応させる |
| **ヘッダの欠落** | `e01` と `w11` は **2 月ブロックの「日Sun」だけ**テキスト層に無い。84 個揃う前提だと落ちる | 列の x は全ブロック共通なので「列の中心 → 曜日」の対応表を作る。左右それぞれ日〜土の 7 個が揃うことを検査 |
| **ヘッダ行の並び** | 「…にお住まいの方」は 1 行目とは限らない。`e03`・`e07` は「東 ③」だけが 1 行目に来る | 行を決め打ちせず全行から探す。地域ラベル (東①〜西⑫) はファイル名との照合に使う |
| **縦積みセル** | 月末の週は「24/31」のように 1 セルに 2 日が入る | 数字を 2 つに割り、**両方について列の曜日と日付の曜日が一致すること**を検査 |

## 設計上の判断

- **`foldCourses` しない。** 24 地域の規則は 15 通りしかなく 9 組が重複する。畳むと区が別物として
  運用している東西の地域が潰れる。`course` は区の呼称 (`e1`〜`e12` / `w1`〜`w12`)、
  `course_name_ja` は「東1」〜「西12」。
- **年末年始は `unknown_periods`。** 全 24 地域で 12/31・1/1・1/2 のセルだけが空だが、
  PDF 自身が「改めて…お知らせいたします」と確定を留保している。`cancelled` は
  「収集なし」の断定なのでソースの主張を超える。12 月の告知が出たら overrides へ落とす。
- **上赤塚町・下赤塚町は収録しない。** ABR には現存するが区の日程資料に一度も現れない。
  推測でデータを作らない。build がこの 2 件だけを名指しの例外として通す。

## 検査

`build.mjs` が毎回やること。

- 索引の曜日規則と PDF の曜日規則の一致 (70 行 × 3 品目 = 210 セル)
- 町字の網羅 (ABR 136 件 − 未公表 2 件 = 134 件をちょうど被覆。二重計上も検出)
- 規則から欠ける日が年末年始の 3 日だけか (他に例外があれば止まる)
- 自己検証: 生成 rules の再展開が PDF の実日付と全日一致 (8,664 日枠)

`verify.mjs` の 2 系統。

| | 何と何を比べるか | 規模 |
|---|---|---|
| A. 地区割の双方向 | 索引「町丁目 → 地域」 ↔ PDF ヘッダ「地域 → 町丁目」 | 24 地域 / 134 町字 |
| B. 日付レベル | 索引の曜日規則を独立に展開 ↔ 公開した course YAML | 24 地域 × 361 日 = 8,664 日枠 |

`node verify.mjs --tamper` は 5 通りの改竄で各検査が落ちることを確かめる。

## 次の版で気をつけること

- URL は年度で `r8/` が変わる。索引ページから辿り直す。
- **年末年始の告知**が出たら `unknown_periods` を外して休止日を `overrides` に入れる。
- 塗り色が変わると**静かに壊れる** (未知色は無視される)。`extract.py` は凡例の色見本が
  3 色ちょうど 1 個ずつあることを検査しているので、配色変更はここで捕まる。
