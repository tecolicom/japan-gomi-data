# 日高市 ごみ収集日程表抽出 (pdf-extractor/hidaka)

日高市「ごみ収集日程表」(令和8年度 = 2026年4月〜2027年3月) の**全 20 コースが載る 1 本の PDF** から
`municipalities/saitama/hidaka/` の course YAML を生成するパイプライン。

## なぜ後から作ったか

日高は 2026-07 に収録されたが、**生成器が残っていなかった**。course YAML のヘッダは
`Auto-generated by tools/pdf-extractor (extract-hidaka-batch)` と名乗っているのに
その生成器は存在せず、`make regen` の検査対象からも外れていた。しかもヘッダは
**「人間による目視レビューは未実施」**と断っている。

飯能 (`tools/pdf-extractor/hanno`) が同じ状態で、A-1 コースの読み違いを 4 か月ぶん
配信していた。日高も同じ穴が空いたままだったので塞いだ。

**照合の結果、収録済みデータに誤りは無かった** (20 コース × 365 日 = 7300 日枠で不一致 0)。

## 一次ソース

- 案内ページ: https://www.city.hidaka.lg.jp/soshiki/shiminseikatsu/kankyo/haikibutsutaisaku/gomi/syusyu_hannyu/27861.html
- 日程表 PDF: https://www.city.hidaka.lg.jp/material/files/group/13/reiwa8nendogominitteihyou.pdf

全戸配布される 4 ページの大判 (949.6 × 1338 pt)。3・4 ページ目が「地区別ごみ収集日程表」で、
コースごとに切り取って貼れるようになっている。ライセンス明示なしの通常ページ。

## パイプライン

```
node fetch.mjs [--force]                   # 案内ページ + 日程表 PDF を cache/ へ
python3 extract.py cache/<pdf>             # 表 → コース別の実日付 JSON
  > cache/extracted.json
EXTRACTED_AT=YYYY-MM-DD node build.mjs     # JSON → course-*.yaml (自己検証つき)
node verify.mjs                            # 抽出結果と course YAML を全日付で照合
```

`extract.py` は `pdfplumber` を使う。飯能と違い**テキスト層があるので色ベース抽出は要らない**。

> **環境の注意**: この環境の既定 `python3` (pyenv 3.13.15) には pdfplumber が入っていない。
> 入っているのは 3.10.2 の方で、秩父広域・青梅・飯能も同じ状況。extractor 側の問題ではない。

## 表の構造 (extract.py)

コースごとに 7 行 × 14 列の表が 1 つ。`pdfplumber` の `find_tables()` がそのまま復元する。

```
行0  コース番号1 | 行政区名 | 高萩北 旭ケ丘１・２ 駒寺 栄新田 森高
行1  可燃ごみ | 分 別 | 4月 | 5月 | … | 3月
行2  月･木曜日 | 古紙･古布 | 8・22 | 13 | 10 | …
行3           | ビン･カン    | 24    | 22 | 26 | …
行4           | ペットボトル | 7・21 | 5・19 | …
行5           | 有害ごみ    |       | 20 |    | …   ← 空欄はその月に収集なし
行6           | 粗大･金属   | 10    |    | 19 | …
```

- セルは「8」「8・22」形式。`^\d{1,2}(・\d{1,2})*$` に合わないものは throw する。
- 1〜3 月の列は **2027 年**。
- **コース番号 10 以降は黒丸に白抜きの数字**で、テキスト層では 1 文字の制御コード (`\x1a`) に
  なりコードポイントが取れない。**1〜9 は普通に読める**ので、表を「ページ → 左右の段 → 上から」
  で並べた順と読めた番号が一致することを検査したうえで、10 以降をその並びで補っている。
  食い違えば throw する。
- **「市では収集しません。地域の集団資源回収に出してください。」**が 12 列ぶんを占める行がある
  (古紙・古布を市が収集しないコース。7 コース該当)。日付ゼロ + note として扱う。

### 表の外にある情報

表の直下の「※注意」から取る。**曜日から推測しない。**

- 可燃ごみを休む日 (施設の定期点検)。月木コースは 5/4・12/31、火金コースは 5/5・1/1
- 区単位の例外 (「※注意２ 下鹿山区は、古紙・古布を市では収集しません」)。
  現行スキーマは規則をコース単位でしか持てないので、該当品目の `note` に原文で残す

## 種別マッピング

| PDF 表記 | category |
|---|---|
| 可燃ごみ | `burnable` (weekly) |
| 古紙･古布 | `paper_cloth` |
| **ビン･カン** | `glass_bottle` + `beverage_can` |
| ペットボトル | `pet_bottle` |
| 有害ごみ | `hazardous` |
| **粗大･金属** | `oversized` + `metal` |

「ビン･カン」「粗大･金属」は同日収集の 2 品目をまとめた市の呼称なので構成カテゴリへ分解する
(日程情報の欠落はゼロ)。

## 規則の表現

可燃だけ `weekly`、資源 7 品目はすべて `monthly_specific` (実日付列挙)。**これが正しい表現**で、
飯能のように `monthly_nth` へ畳むことはしない。日高の資源は月内 n 回目では表せないため:

- びん・缶は通常 第4金だが **7〜9 月だけ第2・4金** (季節で頻度が変わる)
- 粗大・金属は **隔月 (偶数月) 第3金**
- 有害は **年4回 (5・8・11月と2月)**

`docs/drafts/2026-07-20-meta-rule-format-draft.md` の被覆率分析でも、日高は
「発行カレンダー自体が月ごとに変則な日付指定型で、monthly_specific 退避が正しい表現」とされている。

## 照合 (verify.mjs)

```
20 コース × 365 日 = 7300 日枠、不一致 0
```

抽出を 1 日ぶん書き換えて回すと、その日と移動先の 2 日が差分として出ることを確認済み。

## 収録済みデータとの差

生成物と収録済みデータ (2026-07 収録) を突き合わせた結果:

- **rules は 19/20 コースで完全一致**。残る 1 件は course 13 の `paper_cloth` の note の文言で、
  収録済みが「下鹿山区は市では収集しません。…」と縮めているのに対し、生成は PDF の原文
  「下鹿山区は、古紙・古布を市では収集しません。…」をそのまま使う (ソースを直さない方針)
- **overrides の日付は 20/20 一致**。ただし**形式を統一した**。収録済みは
  `{category: burnable, cancelled: true}` が 20 件・`{cancelled: true}` が 20 件と混在していた。
  `categoriesOn` は `cancelled` があれば category を見ずに全休止として扱うので挙動は同じ。
  生成は後者に揃えている
