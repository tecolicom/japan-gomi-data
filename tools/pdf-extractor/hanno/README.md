# 飯能市 家庭ごみ収集カレンダー抽出 (pdf-extractor/hanno)

飯能市「家庭ごみ収集カレンダー」(令和8年度 = 2026年4月〜2027年3月) の**コース別 PDF 6 本**から
収集日を機械抽出し、`municipalities/saitama/hanno/` の収録内容と照合するパイプライン。

## なぜ後から作ったか

飯能の course YAML は 2026-04 に収録されたが、**生成器が残っていなかった**。
YAML のヘッダは `Auto-generated by tools/pdf-extractor` と名乗っていたのに
`tools/pdf-extractor/hanno/` は存在せず、`make regen` の検査対象からも外れていた
(`scripts/check-regen.mjs` は生成器の無い自治体を skip する)。

その状態で 2026-08-14 に**読み違いが 2 件見つかった**。A-1 コースの

- `pet_bottle` が第1・3・**5**水曜 (実際は第1・3水曜のみ。第5水曜はプラだけ)
- `paper_cloth` が第2・4・**5**火曜 (実際は第2・4火曜のみ。第5火曜は収集なし)

で、年 7 日ぶん誤った収集日を配信していた。人が PDF を見るまで誰も気づけなかったのは、
**機械が照合する経路が無かったから**。この extractor はその穴を塞ぐために起こした。

## 一次ソース

- 案内ページ: https://www.city.hanno.lg.jp/soshikikarasagasu/kankyokeizaibu/cleancenter/4/893.html
- コース別 PDF: `https://www.city.hanno.lg.jp/material/files/group/22/2026<slug>.pdf`

| コース | slug | 地区 |
|---|---|---|
| A-1 | haraichibanaguri | 原市場・名栗 |
| A-2 | chuuoiminami | 中央南 |
| A-3 | kaji | 加治 |
| B-1 | higashiaganoagano | 東吾野・吾野 |
| B-2 | chuuoukita | 中央北 |

ライセンス明示なしの通常ページ。市のオープンデータに収集日程データセットは無いため、
**収集日という事実データを抽出**して収録する (練馬・杉並・調布・青梅と同じ整理)。

## パイプライン

```
node fetch.mjs [--force]                       # 案内ページ + コース別 PDF 6 本を cache/ へ
python3 extract.py cache/2026<slug>.pdf        # カレンダー PDF → 品目 × 日付 の JSON
  > cache/extracted-2026<slug>.json            #   (6 本ぶん回す。build/verify がこれを読む)
EXTRACTED_AT=YYYY-MM-DD node build.mjs         # JSON → course-*.yaml (自己検証つき)
node verify.mjs                                # 抽出結果と course YAML を全日付で照合
```

`course-*.yaml` はこの build の生成物なので**手で編集しない**。直したいときは生成器を直して
`make regen HANDLE=hanno` する。`meta.yaml` / `taxonomy.yaml` / `facts.yaml` / `survey.yaml` は
生成しないので、そちらは手書きが正典。

`extract.py` は `pdfplumber` / `numpy` / `Pillow` と `pdftoppm` (poppler) を使う。

> **環境の注意**: 2026-08-14 時点で、この環境の既定 `python3` (pyenv 3.13.15) には
> これらが入っていない。pdfplumber 等が入っているのは 3.10.2 の方で、秩父広域・青梅の
> extractor も同じ理由で既定の `python3` では動かない。extractor 側の問題ではないので
> ここでは回避策を入れていない。

## PDF の構造 (extract.py)

InDesign 製の 2 ページ。**テキスト層が全く無い** (pdfplumber の `chars` が 0)。
品目名も日番号もアウトライン化された図版なので、文字は一切読まない。
読むのは「暦で決めたセル領域に、どの品目色が塗られているか」だけ
(秩父広域 `tools/pdf-extractor/chichibu-koiki` と同じ方針)。

ただし飯能の PDF は**罫線が本物のベクタ線として残っている**ので、秩父のように四隅座標を
ハードコードせず、毎回罫線からグリッドを復元する。市がレイアウトを動かしても座標がずれない。

1 ページに 6 ヶ月ぶんのブロックが 2 列 × 3 段。1 ブロックは

```
曜日ヘッダ行  高さ ~11pt   ← 段の目印。左右 2 ブロックぶんの列罫線 16 本がここに並ぶ
第1週         高さ ~42pt
 …
最終行        高さ ~21pt × 2 段
```

- **列幅は不均等** (日曜・土曜が狭い) なので等分割せず、罫線の実測値をそのまま使う。
- **最終行の 2 段は「その列に 6 週目の日がある場合だけ」別々の日になる。**
  6 週目が無い列では 2 段ぶんが 1 つの縦長セルで、そこに品目が 2 つ縦積みされる。
  上段だけを見ると下の品目を丸ごと落とす (実際、最初の実装はこれで 24 日ぶん取りこぼした)。
- 行数が暦の週数より多い月がある (最終行の下に空段が残る)。暦の週数だけ上から使う。

### 品目は色で取る

| 品目 | RGB (150dpi 実測) | category |
|---|---|---|
| 可燃 | (249, 179, 220) ピンク | `burnable` |
| プラ | (179, 230, 250) 水色 | `plastic` |
| ペット | (179, 227, 182) 薄緑 | `pet_bottle` |
| 粗大 | (249, 178, 137) 薄橙 | `oversized` |
| 不燃 | (255, 245, 64) 黄 | `non_burnable` |
| 有害 | (191, 225, 66) 黄緑 | `hazardous` |
| 飲料缶 | (255, 250, 166) 薄黄 | `beverage_can` |
| 紙布 | (211, 208, 168) カーキ | `paper_cloth` |
| びん | (251, 201, 75) オレンジ | `glass_bottle` |

- **旧 course YAML のヘッダが書き残していた凡例 (灰=不燃・紫=粗大・白=紙布) は実物と違う。**
  上の値は 4 月の既知セルから測り直したもの。読み違えた側の記述は引き継がない。
- 不燃 (255,245,64) と びん (251,201,75) は `|RGB差|` で 59 しか離れていない。閾値で
  「どれかに当たるか」を見ると取り違えるので、**各画素は最も近い参照色 1 つに割り当てる**。
- 未知色は無視しない。既知色から遠い**単色**がセルの 3% かつ 150px 以上を占めたら throw する
  (文字の縁のアンチエイリアスは色が散らばるので単色ではまとまらず、面で塗られた
  品目色だけが塊として残る)。市が配色を変えたり品目が増えたら、黙って落とさず止まる。
- 年末年始の「休業」セルは白地に赤文字で、品目色が無い = 収集なしとして正しく落ちる。

## 照合 (verify.mjs)

抽出結果と収録済み course YAML を、収録期間の**全日付 × 全コース**で突き合わせる。

```
6 コース × 365 日 = 2190 日枠、不一致 0
```

この照合には 2 つの役目がある。

1. **独立検証。** course YAML は別の経路で作られた手書きの正典。ピクセルだけを見る抽出が
   同じ日付集合を出すなら、2026-08-14 の修正が正しかったことの独立な裏づけになる。
   実際、修正前の YAML (`HEAD~1`) に対して照合すると**ちょうど 7 日**の差分が出て、
   それが手で直した 7 日 (4/29・7/29・9/30・3/31 のペット、6/30・9/29・3/30 の紙布) と
   完全に一致する。**検査が実際に効いていることの確認**になっている。
2. **回帰検査。** 以後は extract.py と course YAML のどちらがずれても差分として出る。
   生成物を 1 日ぶん書き換えて回すと、その日と移動先の 2 日が差分として出ることを確認済み。

## 規則の表現

`_lib/classify.mjs` は設計上 `monthly_nth` を出さない (実日付があるなら `monthly_specific` で
厳密に表せるうえ、年末年始の休止で周期がずれる自治体では `monthly_nth` が成立しないため)。
そのため収録当初の手書き YAML にあった `monthly_nth` (第1・3水曜 等) は、生成物では
`monthly_specific` (実日付列挙) になっている。可燃とプラは `weekly` のまま。

切り替えのとき日程は 1 日も変えていない (2190 日枠で一致を確認)。ファイル名だけ
`writeCourses` の規約に従って `course-A1.yaml` → `course-A-1.yaml` に変わった。
`metadata.course` の値 (`A-1`) は据え置き — 下流の city.tecoli がコースの識別と表示に
使っているのはファイル名ではなくこちら。

## areas

PDF はコース名も町名も図版なので、コース → 町名・yomi の対応は `sources.mjs` の設定として持つ
(表記と yomi は市の地区割と既存収録に合わせてある)。ピクセルから読めるのは
「どの日にどの色が塗られているか」だけで、それ以外を PDF から推測することはしない。
