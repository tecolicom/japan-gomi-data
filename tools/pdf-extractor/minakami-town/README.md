# みなかみ町 ごみ収集カレンダー抽出 (pdf-extractor/minakami-town)

みなかみ町「令和8年度後期(令和8年10月～令和9年3月)予定表」の**地区別カレンダー PDF** から
`municipalities/gunma/minakami-town/` の course YAML を生成するパイプライン。
meta.yaml / taxonomy.yaml は生成しない (手書きが正典)。

## 一次ソース

- 案内ページ: `https://www.town.minakami.gunma.jp/life/09sumai/gomi/2017-0117-1345-71.html`
- 地区別 PDF: `files/20261001__gomi_calendar_{minakami_1..6,tsukiyono_1..9,niiharu_1..3}.pdf` (`sources.mjs`)
- **収録期間 2026-10--2027-03**。町は半期ごとに版を出す (4月起点の前期・10月起点の後期)。
  ファイル名の `20261001` も版ごとに変わるはずなので、次の版では `sources.mjs` を直す。
- **新治地区 (niiharu_1〜3) は収録しない。** 資源物が「行政区によって決められています」で日付が無い
  (`meta.yaml` / `survey.yaml` 参照)。
- ライセンス明示なし。収集日という事実データを抽出して収録する。

## パイプライン

```
node fetch.mjs                          # 案内ページ・PDF 15 枚・ABR 町字マスター (群馬県版) を cache/ へ (--force で取り直し)
EXTRACTED_AT=YYYY-MM-DD node build.mjs  # cache → 2026-10--2027-03/course-*.yaml (照合つき)
node verify.mjs                         # 生成 YAML を読み直して日付表・表の文と全日比較
```

`extract.py` は PDF の語と記号の座標を JSON で出すだけで、解釈は `parse.mjs` が行う。

## PDF の構造 (parse.mjs)

A3 横 1 ページ、テキスト層あり。罫線は rect だけ。

- **見出し**: 「令和８年度 水上地区ごみ収集カレンダー 藤原・粟沢・綱子・幸知」。末尾が地区名 (area)。
  見出しの高さは PDF ごとに 36〜58pt とばらつくので、位置ではなく「〜地区ごみ収集カレンダー」の語で探す。
- **上半分の表**: 収集曜日 / 記号 / 分別区分 / 分別内容 / 注意事項。行は 5 つで並びは全 PDF 共通。

  | 記号 | 分別区分 | 収集曜日の例 |
  |---|---|---|
  | ● | 生ごみ・燃やせるごみ | 毎週火・金曜 / １月１日を除く |
  | (なし) | プラスチック・燃やせないごみ | 毎週水曜 / １２月３０日は除く |
  | ■ | かん・びん・ペットボトル | 毎月第１・３木曜 / 1月は第2・4金曜 |
  | ▲ | 電池類・蛍光管類・古紙類 | 毎月第２・４木曜 / 1月は第3・5金曜 |
  | 衣 | 衣類 | 10月と1月の第３木曜 |

  **行の境界は罫線でなく、品目列の語の並び順から決める** (rect の水平線は PDF によって欠けている)。
  品目列の語が上の順にちょうど並ぶことを assert し、隣の行の語との中点を境界にする。
  「除く」は「を除く」と「は除く」の両方がある。
- **下半分の日付表**: 6 か月 (3 列 × 2 段)。日番号の下の行に ■ ▲ 衣 の印だけが付く。
  毎週の品目には印が無い。印は「同じ列で、すぐ上の日番号」の日に付ける。日番号が 1..月末日で、
  曜日の列と暦の曜日が一致することを全日 assert する。
- **注記**: 表の下の ※ と日付表の下の ※ は、知っているものだけを通し、知らないものは throw する。
  - 「※須田貝・青木沢地区のプラスチックは毎週火曜日に収集します。」(minakami_1) → 別 course `minakami-1-sudagai`
  - 「※資源ごみ、古紙類、燃やせないごみの収集場所」(月夜野) → 集積所の一覧。日程の情報は無い

罠:

- **月見出しを字の大きさで選べない。** tsukiyono_1 は 1〜3 月の見出しが 10.6pt で、日番号 (11.8pt) より小さい。
  「すぐ下に曜日見出しの『日』がある『N月』」で見分ける。
- 日付表の下に集積所の一覧がある PDF (月夜野) では、最下段の月の範囲をその ※ の手前で切る。

## 規則の作り方 (build.mjs)

規則は**表の文から作る**。日付表から推定 (`classifyRules`) はしない — 衣類は期間内 2 日しか無く、
`foldMonthlyNth` だと monthly_nth に畳まれて残りの月に偽の override が生える。

- 毎週の行 → `weekly`。「〜を除く」の日は cancelled override
- ■ ▲ → `monthly_nth`。「1月は第…」は category override (その日の monthly 品目を全部並べる)。
  例外で収集が無くなる日 (tsukiyono-4/6/7 の 1/1) は cancelled
- 衣 → `monthly_specific` (2 日)

build の中で 2 つ照合し、どちらかが合わなければ書き出さない。

1. 表の文の日程のうち ■ ▲ 衣 の品目が、日付表の印と全 182 日一致する
2. rules + overrides を `expandRange` で再展開した結果が、表の文の日程と全 182 日一致する

## areas

PDF の見出しの地区名 (行政区) をそのまま使う。ABR 町字マスター (pref10、lg_code 104493) と
名前が完全一致したときだけ yomi / machiaza_id を付ける。括弧書きは括弧の前の名前で引く。
読みのある area を読みの昇順に並べ、読みの無い area はその後ろに印刷順で置く。

## 照合 (verify.mjs)

外部の独立ソースは無い。

1. 生成 YAML を再展開して、PDF を読み直した日付表の印 (■ ▲ 衣) と全日比較 — 15 枚 × 182 日 = 2,730 日枠
2. 毎週の品目を、表の文の曜日と「〜を除く」から数え直して全日比較 (自己照合)
